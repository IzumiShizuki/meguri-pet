## Why

此前验证集中于能力入口和单次发送，尚未将会话重开、输入检查小模型、独立规划模型、RAG 返回及上下文恢复作为连续生命周期验证。用户需要后续对话在取消、超时、重启或依赖失败后仍然可发送，并且失败原因和实际能力保持一致。

## What Changes

- 验证并修复桌面新会话、应用恢复与异步旧回调之间的状态隔离，保证立即发送下一条消息。
- 补齐用户明确的输入小模型检查/改写入口，再进入主流程；保留原文和原始权限/操作意图，失败时回退原文。独立规划模型另外验证，不将其当作输入小模型。
- 验证 Java Core 到 Python RAG/记忆桥接的成功、空结果、故障、超时、取消和迟到返回。
- 补充跨多轮、跨会话及持久化恢复的集成回归，提供可复现实验与覆盖矩阵。
- 明确模拟供应商、实际服务与尚未部署代码的验证范围，保留已有真实 PostgreSQL 恢复证据。

## Capabilities

### New Capabilities

- `dialogue-lifecycle-isolation`: 新会话及恢复期间的状态和异步事件隔离。
- `dialogue-model-retrieval-resilience`: 模型分工、RAG 返回和依赖失败下的多轮对话恢复。

### Modified Capabilities

无。

## Impact

桌面 conversation store、Java Core 会话/规划/检索与 Python 桥接边界、相关测试和诊断文档。测试使用临时目录、模拟用户与回环随机端口；实际服务测试仅使用未绑定模拟身份，不向 QQ 联系人发消息，不切换线上模型或写入正式用户记忆。
