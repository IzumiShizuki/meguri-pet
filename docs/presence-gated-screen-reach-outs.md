# 主动搭话与屏幕文字观察

桌宠仅在最近一次系统鼠标或键盘操作距现在不足 600 秒时，尝试主动搭话、播报主动新闻或观察前台屏幕文字。达到 600 秒、锁屏、休眠或无法读取活动状态时暂停；恢复后需要新的系统操作。电脑一直开着不会被当作人在电脑前。

“设置 → 陪伴与主动性”显示本机活动状态和屏幕观察状态。“允许主动观察屏幕文字”可单独关闭；新安装默认关闭，本次本机部署依照用户明确请求开启。关闭主动性、远程 AI 授权或屏幕观察开关也会停止对应工作。明确设置的提醒与确认的承诺跟进保留原有规则。

系统活动与聊天冷却是两个计时器。在其他软件中操作能证明人在电脑前，但不会重置与桌宠交互后的等待时间。主动性高/普通/低分别等待约 15/45/120 分钟，另保留原有 08:00–22:00 时段、每天最多三次、未回复抑制和语音/编辑/专注状态检查，因此开启后不会立即连续发言。

观察使用 Windows 本机 OCR 读取前台窗口文字；跳过常见凭据、隐私窗口和桌宠窗口。只在符合主动搭话条件时尝试一次，最多 1,000 字符发送到当前配置的 AI。截图只在内存中处理，不写入文件或剪贴板，也不上传原图。它能理解可识别文字，不能代替完整图像视觉。失败或无文字时继续普通搭话，不虚构看见的内容。

Core 将识别结果作为独立的不可信数据传给无工具的搭话生成器，不创建假用户消息，不自动写正式记忆。原生状态在截图前后、模型请求和交付前复查；主动语音还会在合成完成和实际播放前复查，避免延迟音频越过十分钟截止点。

## 本机部署与回退

源码先提交到 `master`，再合入 `codex/companion-memory-corrections`。部署脚本 `ops/scripts/deploy-companion-branch.ps1` 仅接受指定分支、已合入 master 的精确提交及构建清单哈希；沿用本机 Python、Java、网关和桌宠启动脚本，并保留已有 TTS 服务。

验收与回退文件位于忽略的 `.codex-runtime/active-companion-20261025/`。`deployment-status.json` 记录阶段与运行提交，`release-manifest.json` 记录实际构建哈希。`rollback/` 保留原配置、此前 Core JAR 和集成基线的桌面源码归档；回退时先停止本次验证过的服务，再恢复配置和旧构建，不能重置其他会话的未提交文件。详细验收结果见同日部署报告。

本机已有服务以管理员身份运行，因此替换它们必须通过 Windows 正常 UAC 提权。部署不修改系统提权策略或启动任务权限。
