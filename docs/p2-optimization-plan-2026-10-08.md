# P2 优化计划与统筹（2026-10-08）

目标是完成三个 P2 项目的可审查实现。主代理负责需求与接口、OpenSpec、交叉审查、集成验收；三个 `gpt-6-luna` 编码代理分别承担下面的工作。所有代码基于当前工作区增量修改，保留已有未提交成果。

| 项目 | 实施内容 | 交付与验收 | 编码负责人 |
| --- | --- | --- | --- |
| 陪伴导演与主动性 | 显式专注状态；关闭/低/正常/高主动性；复用静音、音量、桌面/Galgame 语音设置；冷却、有限队列和过期；用户确认的本地承诺到期跟进；表现偏好重置/撤销 | 设置界面可操作；专注/对话/播音中暂缓主动表达；静音仍可显示文字；取消承诺后不再跟进；关闭历史保存清除持久内容 | director_luna |
| 表情与播放一致性 | 保存会话/回合/事件级播放账本；副作用前记录；文字及时更新；播音实际开始/结束驱动状态；取消代次隔离旧回调；恢复静态表情；显式回放独立编号 | 重连/重载不自动重播；会话互不串扰；存储失败不影响文字；慢 TTS 不阻塞文字；旧音频/动作不污染新回合；原有手动回放可用 | playback_luna |
| 核心代码与文档整理 | 提取 TurnOrchestrator 的响应生成/训练监督职责；保持协议、取消、训练和恢复行为；核对 Python mock 与 Java 启动链、环境开关；记录后续拆分边界 | 有职责完整的协作模块与行为回归；README 以实际配置为准；验收记录区分自动通过、真人听感和外部资源前提 | core_luna |

实施顺序：先建立规格与接口，再让三路 Luna 并行编码；导演与播放代理直接对齐接口并由主代理确认。实现期间主代理检查边界、发现的问题交回对应 Luna 修正。最后执行桌面单元测试、类型检查、构建和 Java 回归，逐条核对规格并写交付报告。OpenSpec 变更为 `optimize-p2-companion-presentation-and-core`，本次不自动归档。

专注以用户显式设置为准，不从屏幕观察推断。承诺跟进要求桌面运行，只处理明确确认的本地事项，不把模型一句承诺自动变成事实或远程任务；TimePrism 仍负责既有服务器提醒。账本采取“先记录，再播放”，崩溃时可能跳过一次效果，用户仍可主动回放。同源窗口可通过 Web Locks 串行认领，不承诺跨进程分布式恰好一次播放。

回滚入口是关闭主动性、恢复表现偏好或回退本次代码；偏好继续兼容原版本，不修改远端服务和模型路由。真实角色口吻、真人听感、外部 Live2D/TTS 资源下的节拍另记人工验收，不能以单元测试代替。P1 的训练、召回、速度和连续语音交互保持独立范围。
