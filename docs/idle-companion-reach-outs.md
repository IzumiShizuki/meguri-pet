# Meguri 主动搭话

桌面在最近完成一次真实聊天后，会在空闲时尝试接一个自然话题。它使用现有 Meguri 人设和当前会话最近的对话；没有合适的话题时可以保持安静。

在设置的“主动性”选择频率：

| 档位 | 至少连续空闲 | 两次主动通知的最短间隔 |
|---|---:|---:|
| 关闭 | 不搭话 | 明确设置的提醒与本机跟进仍可用 |
| 低 | 120 分钟 | 4 小时 |
| 普通 | 45 分钟 | 90 分钟 |
| 高 | 15 分钟 | 30 分钟 |

桌面每分钟检查一次。舞台启动后重新等待空闲时间，不立即补发旧话题；点击、输入、窗口隐藏/恢复都会重新计时。没有完成过聊天时不凭空打招呼。每次交流后最多一次未回应的搭话，每个本地日最多三个投递名额；跨会话和舞台重启保留一个只有日期和数量的本机计数，午夜重置。投递结果不确定时保守占用名额，避免重复打扰。

以下情况保持安静：22:00–08:00（本机时区）、专注模式、正在发消息/播放语音/语音通话、编辑输入框、舞台隐藏、聊天隐藏、打开工作/技能面板、AI 对话许可未接受或已撤回。静音时可显示文字。生成期间发生用户操作或切换会话时丢弃待发内容，不把它排队到另一段对话。

搭话通过独立 Core 接口生成，不伪造用户消息，不创建工具任务，不触发正式记忆提取或训练反馈。只有桌面接受显示后才确认写入助手上下文，以便用户接着回复。没有显示的候选在十分钟后失效；服务忙、断网、旧版 Core 不支持该接口或模型不支持时保持安静，至少十五分钟后才会重试。

Core 和桌面必须配套更新。接口为 `POST /v1/companion/reach-outs` 和 `POST /v1/companion/reach-outs/{id}/delivered`，使用现有网关身份与会话校验。普通文字/语音路径及网关的 Core 选路保持现有配置。模型调用只有最近八条有界上下文；本轮尚未加入正式长期记忆检索或额外联网检索。

显示与服务端确认之间若进程崩溃，可能只留下本机搭话记录；舞台仍在运行时会有界重试确认，确认过期或上下文已改变则不再追加。模型自然度和真实麦克风/远端服务的效果仍需运行后体验；自动化验证覆盖调度、取消、身份隔离、去重和助手上下文连续性。
