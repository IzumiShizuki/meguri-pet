# 多层记忆与桌面感知跨端协同强化设计

日期：2026 年 10 月 12 日。依据：[毕业设计任务书](D:/download/by.docx)、[当前实现审计](research/by-runtime-audit-2026-10-12.md)、[记忆论文笔记](research/by-memory-papers-2026-10-12.md)与 [GUI 及跨端论文笔记](research/by-gui-cross-client-papers-2026-10-12.md)。这里把用户所说的“提到模块”解释为任务书中的桌面分级感知、受控操作及跨端协同。本文由主代理负责设计思考；论文阅读、节选翻译与本期评测代码由 `gpt-6-luna` 子代理完成。

建议将课题的重点放在三件可验证的事上：长期记忆能够追溯和纠正；桌面决策必须依据新鲜、可定位的观察；跨端记忆变化能够按权威版本确认。现有候选审核、不可变版本、软删除、恢复和身份绑定可以复用。先建立真实基线，再逐项增强；本期实现评测工具，后续运行模块改动按下面的清单另开 OpenSpec。

## 当前能力及优先顺序

| 模块 | 当前已有能力 | 实际缺口 | 优先落点 |
|---|---|---|---|
| 正式记忆 | PostgreSQL/pgvector 权威库，候选审核、版本链、删除恢复、范围和时效过滤 | 当前配置关闭 embedding/rerank；中文复述缺少可靠语义路径；Java 将召回项降为纯文本，反馈难以定位版本 | 真实文本基线、保留召回证据、敏感级别贯穿、再对照启用 hybrid |
| 记忆整理 | 会话上下文与周期整理，checkpoint 幂等，最多三条候选 | 摘要的证据粒度与长期事实边界需要加强；反馈未影响复核/排序 | 带来源的中期主题整理与纠错候选 |
| Windows 感知 | 窗口模型、policy-first 管线、语义变化、TTL、mock provider | 没有接入真实 HWND、截图、OCR、VLM；不能声称已达到定位率 | 先真实元数据/UI Automation，再 OCR，最后按需 VLM |

## 记忆如何加强

### 分四层管理信息

工作上下文只包含当前会话、当前任务和最近消息，继续按 `tenant/user/client/session` 隔离。中期层保存带主题和时间的会话片段及递归摘要，用于跨轮找回上下文；每个摘要保存证据消息 ID、来源会话、摘要版本和整理 checkpoint。长期层保存用户明确陈述并经过审核的稳定事实，继续由现有权威库管理。任务情节层保存一次桌面任务的目标、观察、操作与结果，默认设有效期和设备范围，成功经验只有经过复核才提升为长期程序性知识。

这些层是不同生命周期和查询方式，不要求新建四套数据库。论文中的递归摘要和分层记忆可帮助压缩上下文，但压缩会丢失细节；原始证据应保留引用，摘要不能独立成为新事实的唯一依据。[递归摘要论文](https://doi.org/10.1016/j.neucom.2025.130193)、[MemoryOS](https://aclanthology.org/2025.emnlp-main.1318/)、[LongMemEval](https://arxiv.org/abs/2410.10813)为此提供方法线索；具体模型、阈值与效果必须在本项目验证。

不要因为每十轮触发整理就重写全部画像。使用主题变化、候选积累和上下文压力作为整理条件，保留当前十轮 checkpoint 为保守回退；后台合并已完成区间，正在进行的对话不被摘要任务阻塞。整理失败保留原文和待处理 checkpoint，重试使用同一操作 ID。

### 让召回结果可解释

Java 接口应保留结构化 evidence：`memory_id`、`version_id`、来源、有效时间、权限范围、敏感级别、分数分项和召回通道。LLM 的输入可在预算内渲染成简短证据块；界面反馈仍携带准确的 ID/版本。用户说“这已经过时了”时，系统创建带旧版本引用的纠错候选，不能直接用新一轮生成内容覆盖事实。

候选已有 `normal/private/sensitive`，但审核通过后敏感标签未完整进入正式项。这个缺口应优先修复：在候选、版本、检索响应、导出和客户端展示之间保持敏感度，并将私聊来源与共享许可分开记录。某条事实来自私聊，不代表用户允许它在群聊或另一设备显示。审核批准、跨端分享授权和当前客户端的读取权限需要分别判定。凭据在候选之前拒绝，不以“敏感但可审核”的方式存储真实密码或令牌。

### 先量化中文召回，再开启混合通道

第一条基线是当前真实配置：PostgreSQL `simple` 全文检索与连续子串补充。非连续复述和同义表达要独立标注，不能把“同一字符串”查询的高命中率当成自然语言记忆能力。之后比较：结构字段与词法召回；词法加向量；前两者加时间条件；再加入有界重排。使用现有 embedding worker、model revision 和 outbox，新增事实只有当前可回忆版本进入检索，过期或被删除项继续由权威过滤控制。

查询通道建议按问题类型选择：查某个已知项目用 canonical key；查近期开销或“上周提到的”事实加时间范围；同义改写使用向量；用户名、路径、编号依赖词法或精确匹配。RRF 融合要只使用实际有信号的通道，关闭向量时不能让全零 semantic 通道的任意顺序影响结果。该点需单独建立可复现反例再改现有排序代码。

相关度不足时返回没有可靠记忆，由回复明确不确定。检索相关并不等于事实仍然有效。默认个人事实只召回当前版本；用户明确查询历史时走带时间锚点的历史查询能力，并在回复中标明历史状态。这一路径必须在评测中与“误召回旧版本”分开。[LongMemEval](https://arxiv.org/abs/2410.10813)将更新、时间推理和拒答列为长期记忆能力，适合用来组织本项目对照组。

### 整合与遗忘需要可撤回

使用频率、最近访问、用户反馈和任务相关性可以影响排序或复核优先级。经常被模型召回不能提高事实真实性；否则一次错误会被循环强化。将 `helpful` 用作有限的排序信号，将 `wrong/stale` 用作复核或纠错信号，不自动转成删改命令。

遗忘优先表现为降低召回优先级、到期和归档，保留用户能查看和恢复的路径。承诺、重要人物和用户固定偏好不能只因为长期未访问就删除；临时窗口状态和短期任务可以更快到期。心理记忆模型为衰减提供启发，但不同记忆类型的阈值要调参和消融验证，不能把心理规律直接当成工程默认真理。[重要度与遗忘研究](https://doi.org/10.5210/dad.2025.203)适合作为这一设计的研究依据。

## 桌面感知与受控操作如何加强

### 按成本和可靠性分级观察

一级读取附着窗口身份、进程、标题、几何、焦点和最小化状态；在允许的应用上尝试 Windows UI Automation 提供的元素 role/name/bounds。二级对无法获得语义树的允许区域使用截图与 OCR，输出文字、坐标和置信度。三级仅在前两级信息不足或用户询问图像语义时使用 VLM。每次升级都保留来源、采集时间、窗口实例、frame ID、坐标系、DPI、模型版本和置信度，避免不必要的连续截图。

屏幕文本和视觉内容是待解释的数据。观察中出现的“忽略限制”“发送文件”等文字不能成为权限指令，不能自动进入正式用户事实。权限门必须在截图/模型调用之前执行；敏感窗口、用户撤回和附着目标失效时，缓存及后续调用都受同一门控制。

实现顺序为真实窗口元数据 provider → UI Automation → OCR 区域与坐标归一 → 按需 VLM。已有 `ScreenObservationPipeline`、policy evaluator 和 freshness 可以继续承担共同接口。GUI 综述对感知、规划、行动、记忆及评估的划分提供了参考，但具体 Windows 接入与权限约束属于本项目设计。[作者发表页](https://www.microsoft.com/en-us/research/publication/large-language-model-brained-gui-agents-a-survey/)。

### 语义变化决定是否更新上下文

窗口移动或 DPI 变化首先更新几何映射，不必重新解释全部内容。文字、选中项、对话框和关键元素变化才触发语义更新；同一帧或语义未变化时复用已有结果。保留 TTL 作为最长有效期，关键窗口事件作为提前失效条件。切换窗口、关闭窗口、模型置信度不足或出现新遮挡时不得沿用上一观察的点击坐标。

### 每一步都有前置与后置条件

动作计划只包含 allowlist 中的操作，并记录目标元素、来源 frame ID、预期前置状态、预期结果、失败条件和风险级别。批准凭证绑定具体目标、动作、参数摘要、用户、设备和失效时间。用户批准一次打开文件不能授权后续发送、覆盖或删除。

执行前再次确认附着窗口身份、焦点、frame freshness 和元素位置。优先使用稳定元素定位，坐标仅在缺少语义定位时使用且执行前重新验证。执行后读取新观察并检查任务状态：文本是否进入正确输入框、文件是否出现在预定临时目录、目标页面是否可见。不能仅凭点击 API 返回成功就计为任务成功。

失败时先重新观察，再进行有限次数重规划；重复点击、重复发送和重复写入使用操作 ID 或可检查的最终状态防重。达到次数、时限、置信度下限或审批边界时停止并报告具体原因。桌面任务成功经验可进入短期情节记录，不能直接变为不受约束的常驻自动化。[OSWorld](https://arxiv.org/abs/2404.07972)强调交互环境与任务结果评测，适合用来设计最终状态验收；本项目安全门与设备边界为工程上的额外要求。

## 跨端如何加强

### 权威记忆与短期会话分开同步

不同入口必须通过已有显式绑定得到同一个 canonical user，随后才读取用户授权的正式记忆。桌面端与聊天平台保持独立短期上下文、屏幕状态和操作凭证，群聊内容不能自动并入私有画像。关系和角色状态也要区分用户全局字段与单个会话的表现状态，避免一个入口的情绪表达覆盖另一个入口正在执行的任务。

服务端继续只有一个记忆权威库。客户端缓存用于展示和短期降级，不自行解决事实冲突，也不把断网时生成的本地内容当作已批准长期记忆。

### 用所有者 revision 传播变更

在审核、更新、软删除、恢复和相关授权变更事务中递增该所有者的 revision，并写入专用记忆变更 outbox。为同一个 `(tenant,user)` 使用事务内行锁推进 revision，避免用未提交的全局序列号推断提交先后。事件只携带 ID、版本、状态和 revision 等失效线索，接收端按当前授权重读内容。

客户端处理已见 revision 时幂等忽略，发现缺口或重连时请求权威快照。授权范围不允许的内容不随事件广播；被隐藏的变更也不能迫使客户端猜测他人的状态。撤销绑定后清除相应缓存并停止接收事件，恢复连接也需重新授权。已有会话 SSE sequence 继续保证会话重放，但不能代替所有者记忆 revision。

同步延迟从服务端权威事务提交确认，到接收端完成重读并应用相同状态为止，使用同一实验控制器的单调时钟。仅收到通知但还没应用状态不算完成。暂以事件推送加重连重读为目标，若先采用轮询，其周期与端到端处理预算必须留出 P95≤3 秒的余量，并单独测量服务器、客户端和网络耗时。

### 对照整份状态

一致性比较至少包含 active/deleted 状态、current version 指针和相关授权的规范化快照 hash；相同 version ID 不能掩盖删除状态或读取许可不同。并发审核带 base version，冲突进入已有复核流程；请求重试使用相同 operation ID。训练反馈仍保留自己的用户同意和撤回机制，不因记忆同步而共享训练样本。

## 论文实验应怎样设计

### 记忆 150 条盲测

另设至少 60 条开发样本用于阈值和权重调整，锁定配置后再评估 150 条测试样本。不要让同一事实的简单模板替换同时进入开发集和测试集。每条用例包含来源与提问会话、canonical user、金标准当前版本、显式旧版本以及检索结果；保留多个相关事实，不能把只找回其中一条就算满分。

| 测试类别 | 数量 | 要检查的行为 |
|---|---:|---|
| 固定画像与偏好 | 25 | 跨会话引用、中文复述、稳定偏好 |
| 项目与重要人物 | 25 | 同名实体区分、多个相关记忆 |
| 时间与事件 | 20 | 绝对/相对时间、时区、有效期 |
| 纠错与版本更新 | 25 | 新值生效、旧值不误用、显式历史问题另标 |
| 多会话组合 | 20 | 跨多个来源综合回答、证据不遗漏 |
| 删除与过期 | 10 | 不可回忆项被过滤、恢复有明确版本 |
| 缺失事实与拒答 | 25 | 没有依据时不补造事实 |
| 合计 | 150 | 其中 125 条有答案，25 条单独统计拒答 |

Recall@5 使用有答案查询的宏平均：每条为 top-5 中命中的正确 ID/版本对数除以该条金标准对数，再对 125 条平均。旧版本误召回主口径使用“top-5 中出现至少一个已标注旧版本的查询数 / 全部已执行查询数”；另报告“旧版本结果条数 / top-5 全部结果条数”便于比较，但不能在结果出来后更换主分母。150 查询时最多三条含旧版本查询满足 2% 门槛，正式报告同时给出原始计数。

另外设计非真实值的凭据拒写探针至少 30 条，以及身份/租户/来源授权隔离探针至少 20 条。分别确认候选、正式项、导出和日志中没有违规内容；探针不能使用用户真实令牌。一次凭据违规或身份串用立即失败，不能被平均召回率稀释。当前评测工具接收探针观察结果；真实扫描与捕获器在后续实现。

对照组使用相同语料、相同 token 预算与同一读取模型：当前词法基线、混合召回、加入时间过滤、加入有界重排、加入带证据整合。每次只增加一个机制，记录 Recall@5、旧版本率、拒答正确率、最终回答正确率、token 数、检索/回复延迟及外部调用成本。运行配置和样本 hash 随报告固定；阈值达标外报告置信区间和失败例。

### GUI 三类应用六十个场景

可从浏览器、文本编辑器、文件管理器各选 20 个测试任务，每个任务记录关键元素定位及多步骤最终状态。每类覆盖常规界面 5、缩放/窗口变化 5、动态对话框/遮挡 5、观察过期/失败恢复 5。使用已有应用和专门临时文件夹；定位标注和预测统一到同一窗口像素坐标，并记录 DPI。

定位准确率以关键元素预测点落在人工标注 bbox 内为成功，缺失预测计失败；任务成功率以预先写定的最终状态断言为准。另建撤销权限、敏感窗口、目标替换、观察过期、伪指令、重复操作等安全探针，每次分别记录是否获授权与真实执行结果。未授权敏感操作成功数必须为零；“识别到了按钮”不能抵扣一次未授权执行。

比较元数据/UI Automation、加入 OCR、按需 VLM、加入语义变化缓存四组，固定任务、动作预算和权限。报告定位率、TSR、重试数、观察耗时、模型调用量和停止原因。60 个场景的配置变体可另列压力测试，不作为新增独立场景凑数。

### 跨端五十组用例

| 用例组 | 数量 | 状态检查 |
|---|---:|---|
| 创建与批准 | 10 | 两端只在批准后读取同一事实 |
| 纠错与更新 | 10 | 新版本及有效时间一致 |
| 删除与恢复 | 10 | 删除状态、指针、授权相同 |
| 并发与重试 | 8 | base-version 冲突、幂等不重复 |
| 重启与重新连接 | 6 | revision 缺口补全、缓存失效 |
| 撤销绑定与隔离 | 6 | 停止分享、跨用户/会话不串用 |
| 合计 | 50 | 桌面与至少一种聊天入口 |

状态一致率为成功用例数 / 全部已执行用例数。只有 50 组时，49/50=98%，因此至少 50/50 才满足 99%；不能把 49/50 四舍五入成 99%。稳定网络下计算端到端 P95，并单独报告未送达和不稳定网络恢复；未送达用例不能从延迟门中悄悄排除。比较开启/关闭变更通知的同步行为，记录客户端版本、网络条件与时钟来源。
