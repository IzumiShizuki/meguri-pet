# 查看来源与改正正式记忆

正式记忆支持查看当前版本、来源客户端、来源会话及更新时间。记错的内容可以提交改正候选，确认通过后才会替代原版本。

## 使用流程

1. 打开设置 → 正式记忆，选择一条记忆的「查看来源与改正」。
2. 核对当前内容、版本与来源。来源没有记录时，界面显示「未记录」。
3. 点击「改正这条记忆」，填写新内容和改正原因。正文最多 4000 字，原因最多 1000 字；不要填写密码或密钥。
4. 点击「提交为待审核候选」。此时正式记忆仍保留原内容；界面会提供「查看候选记录」入口。
5. 在候选记录中核对改正内容，再选择「确认记住」或「拒绝」。版本冲突或审核拒绝时，服务会返回实际结果。

取消改正会回到查看状态；收起详情会回到原列表按钮。键盘用户进入编辑时聚焦正文，取消后回到「改正这条记忆」，提交后聚焦「查看候选记录」。

## 失败与版本变化

网络失败后，草稿留在当前编辑器中。直接重试相同内容会复用同一请求 ID，避免响应丢失造成重复候选；修改正文、原因或基准版本后会创建新的提交身份。

如果另一处已更新记忆，旧版本的提交或确认会被拒绝。点击「重新读取当前版本」，核对新的正式内容，再决定是否保留当前草稿继续提交。重新读取不会覆盖已输入的正文或原因。

切换会话、选择其他记忆或关闭编辑器会结束这次编辑。草稿仅保存在当前页面内存中，不写入本地存储；迟到的旧请求结果不会填进新会话。

## 运行版本要求

需要协调更新 Python 正式记忆桥、Java Core、本机网关和桌面渲染资源。现有脚本和权威数据库配置继续使用，不需要迁移数据库或重建记忆。

桥服务通过受保护的 status 响应声明 `memory_detail`、`memory_corrections`，Core 仅转发识别的能力；桌面在两项都可用时显示新入口。旧 Core 或旧桥服务未声明时，已有列表、审核、删除和导出继续使用。

本机网关仅新增 GET `/v1/memory/desktop/memories/{uuid}` 和 POST `/v1/memory/desktop/memories/{uuid}/corrections` 两种受限路径；其他方法、未知路径及非 Meguri 客户端仍被拒绝。身份和凭据由原受信网关提供。

详情接口只输出当前版本的显示字段，不输出原始 provenance、结构化内容或操作者标识。纠错继续经过原 `propose_supersede`、审核和版本并发检查，不直接修改正式文本或关系数值。本功能展示当前版本的来源，不代表提供每条聊天回答的召回解释或完整历史版本浏览。
